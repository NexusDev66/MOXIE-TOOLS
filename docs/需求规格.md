# 需求规格(纠正版)

## 1. 一句话目标
基于 latemai 现有静态 UI,做一条**全自动、真上线**的数据闭环:
> 产品 **AI 清洗** → **权重算法定时排序更新** → 写进**同一个 Supabase** → 静态 UI 展示 → **SEO 预渲染更新**。

## 2. 背景与上一版教训(必看)
- latemai 静态站(`moxie-*.html`)用 `moxie-supabase.js`(客户端 anon key)**直连同一个 Supabase**(`sqvohgcwzhhsvkmyesvs`),读 `moxie_products(status=published)` / `moxie_articles(status=published)`。
- 上一版三个根因:① 误以为要 **HTTP API 对接**(其实同库,直接写)② **从没真部署/跑通**(线上 0 产出)③ 采集源是海外 launch 目录站,**数据全是无名灰产**。
- 纠正:**无 API、直接写库;每步必部署+线上验证;数据要有价值;主链路全 AI 自动**(人工只极小量 QA)。

## 3. 数据策略(已确认:两者都要)
- **头部**:成熟国产+海外 AI 工具种子清单 → AI 清洗 → 直接 published(让站立刻有价值)。
- **新锐**:持续抓取,但用**权重算法 + 流量门槛**筛,只有过阈值才自动 published,junk 不进站。

## 4. SEO 策略(已确认:预渲染/SSG)
静态站是客户端 JS 渲染,爬虫看不到内容 —— 这是 SEO 起不来的根因。必须**预渲染**:读库把内容烤进 HTML + `<title>/<meta>/canonical` + JSON-LD + `sitemap.xml`,再部署。

## 5. 自动化要求
默认**全自动、定时**:AI 清洗、权重排序、新锐入库、SEO 文章、预渲染、sitemap 全部 cron 跑。人工后台只用于极少量 QA,不是主路径。

## 6. 验收口径(每个 Phase 都要"线上可验",不是"本地跑过")
- 打开线上站能看到**真实有价值**的工具,排序合理。
- `sitemap.xml` 线上可访问、含产品/文章 URL。
- 产品/文章详情页 **查看网页源代码**能看到内容 + JSON-LD(证明预渲染生效)。
- cron 真跑过(有运行记录 + 库里数据按时变化)。
